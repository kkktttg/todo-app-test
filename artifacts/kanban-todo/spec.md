## Overview
Trello 스타일의 칸반 Todo 앱. 커스텀 칼럼에서 카드를 드래그&드롭으로 관리하고, 검색·필터·다크모드를 지원하며, 모든 데이터를 localStorage에 저장한다.

## 시나리오

### 1. 칼럼 관리
[상황] 사용자가 칸반 보드에서 칼럼을 추가/삭제/이름변경하면
[동작] 시스템이 칼럼 목록을 즉시 반영하고 localStorage에 저장한다

성공 기준:
- [ ] 초기 접속 시 기본 칼럼 "Todo", "In Progress", "Done" 3개가 표시된다
- [ ] "칼럼 추가" 버튼 클릭 후 "QA" 입력 -> 4번째 칼럼 "QA"가 표시된다
- [ ] "In Progress" 칼럼 이름을 "진행 중"으로 변경 -> 칼럼 헤더가 "진행 중"으로 표시된다
- [ ] "Done" 칼럼 삭제 -> 칼럼이 3개로 줄고 "Done"이 보이지 않는다
- [ ] 카드가 있는 칼럼 삭제 시 확인 다이얼로그가 표시된다
- [ ] 확인 다이얼로그에서 "확인" 클릭 -> 칼럼과 포함된 카드가 모두 삭제된다

### 2. 카드 생성
[상황] 사용자가 특정 칼럼에서 카드 추가 버튼을 클릭하고 필드를 입력하면
[동작] 시스템이 해당 칼럼에 새 카드를 생성하고 표시한다

성공 기준:
- [ ] "Todo" 칼럼에서 "추가" 클릭 -> 제목 "API 설계", 설명 "REST 엔드포인트 정의" 입력 -> 카드가 "Todo" 칼럼에 표시된다
- [ ] 제목 없이 생성 시도 -> "제목을 입력해주세요" 오류 메시지가 표시된다
- [ ] 우선순위 "High" 선택 -> 카드에 High 우선순위 뱃지가 표시된다
- [ ] 마감일 "2026-04-01" 설정 -> 카드에 마감일이 표시된다
- [ ] 담당자 "김개발" 입력 -> 카드에 담당자명이 표시된다
- [ ] 커버 이미지 URL 입력 -> 카드 상단에 이미지가 표시된다

### 3. 카드 인라인 편집
[상황] 사용자가 기존 카드의 필드를 직접 클릭하여 수정하면
[동작] 시스템이 해당 필드를 인라인 편집 모드로 전환하고 변경 사항을 저장한다

성공 기준:
- [ ] 카드 제목 "API 설계" 클릭 -> 입력란으로 전환 -> "API 문서화"로 수정 -> 카드 제목이 "API 문서화"로 표시된다
- [ ] 카드 설명 "REST 엔드포인트 정의" 클릭 -> 텍스트 영역으로 전환 -> "GraphQL 스키마 정의"로 수정 -> 카드 설명이 "GraphQL 스키마 정의"로 표시된다
- [ ] 우선순위를 "High"에서 "Low"로 변경 -> 뱃지가 "Low"로 변경된다
- [ ] 편집 중 Escape 키 -> 변경 사항이 취소되고 원래 값이 유지된다

### 4. 카드 삭제
[상황] 사용자가 카드를 삭제하면
[동작] 시스템이 확인 후 카드를 제거한다

성공 기준:
- [ ] 카드의 "삭제" 버튼 클릭 -> 확인 다이얼로그 표시 -> "확인" 클릭 -> 카드가 목록에서 사라진다
- [ ] 확인 다이얼로그에서 "취소" 클릭 -> 카드가 그대로 유지된다

### 5. 서브태스크(체크리스트) 관리
[상황] 사용자가 카드 내에서 서브태스크를 추가/완료/삭제하면
[동작] 시스템이 체크리스트를 업데이트하고 진행률을 표시한다

성공 기준:
- [ ] 카드에 서브태스크 "DB 스키마 작성" 추가 -> 체크리스트에 항목이 표시된다
- [ ] 서브태스크 3개 중 2개 체크 -> 진행률 "2/3"이 표시된다
- [ ] 서브태스크 "DB 스키마 작성" 삭제 -> 체크리스트에서 제거된다
- [ ] 모든 서브태스크 완료 -> 진행률 "3/3"이 표시된다

### 6. 드래그 & 드롭
[상황] 사용자가 카드를 드래그하여 다른 칼럼 또는 같은 칼럼 내 다른 위치로 이동하면
[동작] 시스템이 카드 위치를 변경하고 저장한다

성공 기준:
- [ ] "Todo" 칼럼의 카드를 "In Progress"로 드래그 -> "Todo"에서 사라지고 "In Progress"에 표시된다
- [ ] "Todo" 칼럼 내에서 카드 순서를 변경 -> 변경된 순서대로 표시된다
- [ ] 페이지 새로고침 후에도 이동된 위치가 유지된다

### 7. 태그 관리
[상황] 사용자가 태그를 생성하고 카드에 태그를 붙이면
[동작] 시스템이 태그를 저장하고 카드에 표시한다

성공 기준:
- [ ] 새 태그 "Backend" 생성 시 색상 선택 -> 태그 목록에 "Backend" 태그가 해당 색상으로 표시된다
- [ ] 카드에 "Backend" 태그 추가 -> 카드에 "Backend" 태그 뱃지가 표시된다
- [ ] 카드에서 태그 제거 -> 해당 태그 뱃지가 카드에서 사라진다
- [ ] 하나의 카드에 태그 복수 추가 가능 -> "Backend", "Urgent" 두 태그가 모두 표시된다

### 8. 제목 검색
[상황] 사용자가 검색창에 텍스트를 입력하면
[동작] 시스템이 실시간으로 제목이 일치하는 카드만 필터링하여 표시한다

성공 기준:
- [ ] "API" 입력 -> 제목에 "API"가 포함된 카드만 표시된다
- [ ] 검색어 삭제 -> 모든 카드가 다시 표시된다
- [ ] "xyz123" 입력 (일치 없음) -> "검색 결과가 없습니다" 메시지가 표시된다

### 9. 우선순위·태그 필터
[상황] 사용자가 우선순위 또는 태그 필터를 선택하면
[동작] 시스템이 조건에 맞는 카드만 표시한다 (AND 로직)

성공 기준:
- [ ] 우선순위 "High" 필터 선택 -> High 카드만 표시된다
- [ ] 태그 "Backend" 필터 선택 -> "Backend" 태그가 있는 카드만 표시된다
- [ ] 우선순위 "High" + 태그 "Backend" 동시 선택 -> 두 조건을 모두 만족하는 카드만 표시된다
- [ ] 필터 해제 -> 모든 카드가 다시 표시된다
- [ ] 검색어 "API" + 우선순위 "High" 필터 동시 적용 -> 두 조건을 모두 만족하는 카드만 표시된다

### 10. 다크모드
[상황] 사용자가 다크모드를 토글하면
[동작] 시스템이 테마를 전환하고 설정을 저장한다

성공 기준:
- [ ] 다크모드 토글 클릭 -> 배경색이 어두운 색으로 변경된다
- [ ] 페이지 새로고침 후에도 다크모드 설정이 유지된다
- [ ] 시스템 다크모드 설정인 경우 첫 접속 시 자동으로 다크모드가 적용된다

### 11. 데이터 영속성
[상황] 사용자가 데이터를 변경한 후 페이지를 새로고침하면
[동작] 시스템이 localStorage에서 데이터를 복원하여 이전 상태를 표시한다

성공 기준:
- [ ] 카드 추가 후 새로고침 -> 추가한 카드가 그대로 표시된다
- [ ] 칼럼 구조 변경 후 새로고침 -> 변경된 칼럼 구조가 유지된다
- [ ] 태그 생성 후 새로고침 -> 생성한 태그가 유지된다

### 12. 자동 타임스탬프
[상황] 사용자가 카드를 생성하거나 수정하면
[동작] 시스템이 생성일과 수정일을 자동으로 기록한다

성공 기준:
- [ ] 카드 생성 시 생성일이 "2026-03-19" 형식으로 표시된다
- [ ] 카드 수정 시 수정일이 갱신되어 표시된다

## 범위

### 포함
- 커스텀 칼럼 CRUD (추가/삭제/이름변경)
- 카드 CRUD (생성/조회/인라인편집/삭제)
- 카드 필드: 제목, 설명, 우선순위(High/Medium/Low), 태그(복수), 마감일, 담당자(텍스트), 서브태스크, 커버이미지(URL), 생성일/수정일(자동)
- 드래그&드롭 (칼럼 간 이동 + 칼럼 내 순서 변경)
- 사용자 정의 태그 (이름 + 색상)
- 실시간 제목 검색
- 우선순위·태그 복합 필터 (AND)
- 다크모드 (수동 토글 + 시스템 감지)
- localStorage 데이터 영속성

### 제외
- 멀티유저/인증: 싱글유저 localStorage 앱이므로 불필요
- 서버/DB: 요구사항이 localStorage 저장으로 한정
- 카드 간 의존관계/링크: 복잡도 대비 우선순위 낮음
- 이미지 업로드: localStorage 용량 제한(~5MB)으로 URL 링크만 지원
- 칼럼 드래그 순서 변경: 카드 드래그&드롭에 집중, 칼럼 순서는 추가 순서 고정
- 알림/리마인더: 서버 없이 브라우저 알림은 UX 가치 낮음

## 전제 조건

- shadcn/ui 컴포넌트 라이브러리 사용
